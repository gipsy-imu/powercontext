# 周边去哪儿

按用户给定的城市、起点和需求，推荐最多三个独立的步行目的地。每个推荐都须有高德 POI 和对应步行路线的依据。

## 理解需求

- 提取地点类型、步行时间或距离上限、推荐数量和排序偏好。将数量上限取用户要求与 3 中的较小值，未指定时最多给 3 个。区分硬性条件和“优先”“最好”等偏好。
- 使用输入给定的高德起点坐标，按 `经度,纬度` 传给工具。只有文本地址时，可用 `maps_geo` 带城市解析明确地址。若仍有多个合理起点，请用户补充具体位置。

## 查地点和路线

1. 调用高德周边搜索 `maps_around_search`。将起点作为 `location`，把地点类型或明确的店名作为 `keywords`，半径 `radius` 传米数字符串。按用户给的搜索范围或时间预算选择初始半径，未指定时可从 1500 米起查。搜索半径只用于召回候选，最终用步行路线判断限制。
2. 从 `pois` 按 POI ID 去重，检查名称、类目和可核对的城市信息。同一品牌的不同分店按各自的 POI ID 和地址区分。优先核验类型相符且靠近起点的候选。软偏好可结合工具返回的信息判断，缺少依据时标为未核实。
3. 若 POI 缺少坐标、地址或判断硬条件所需的信息，使用 `maps_search_detail` 传该 POI 的 `id` 查详情。用详情返回的 `location`，或者周边结果中同一 POI 的有效坐标作为终点。保留地点原名和高德返回的地址。跳过没有可靠终点、类型不符或硬性条件无法核实的候选。
4. 为每个候选分别调用 `maps_direction_walking`。每次的 `origin` 都用原始起点，`destination` 用该候选自己的坐标。读取同一方案的 `route.paths` 中的 `distance`（米）和 `duration`（秒）。忽略失败、无路线和缺少有效距离或耗时的结果。周边搜索的距离只能用于决定先查哪些候选。
5. 将用户的时间上限换算成秒、距离上限换算成米，用路线的原始数值过滤，再做展示单位转换。“以内”“不超过”包含边界，“少于”不包含边界。有多条可行方案时，按用户的偏好选同一条方案的时间和距离。若首批结果不足，可用等义关键词或在允许范围内扩大半径再查一轮，保留原来的步行限制。单个路线失败时继续检查其他候选。遇到暂时性错误可重试一次，遇到权限或限流错误应如实说明。

## 排序和回答

- “优先近一点”按实际步行距离升序，距离相同再比耗时。“优先快一点”按实际步行耗时升序，再比距离。其他偏好只按已核实的信息排序。没有指定偏好时，先比步行耗时，再比距离。
- 从排好的合格候选中取所需数量。每项给出 **地点名称、地址、预计步行距离、预计步行时间和一句推荐理由**。时间可用“约 X 分 Y 秒”，理由用地点类型、已知特点或已核验的路线数据。高德缺少地址时标记“地址未核实”。安静程度、排队、营业状态等只有工具返回足够依据时才可确认。
- 少于目标数量时简短交代原因。只有超时或类型不符时，说明查询范围内符合条件的地点不足。工具异常导致无法核验时，说明失败的是地点查询还是路线查询。没有合格结果时可建议放宽条件。

例如，用户要求“步行不超过 15 分钟，最多 2 家咖啡馆，近一点优先”，则只保留高德路线耗时不超过 900 秒的咖啡馆，按步行距离取前两家。若两条路线分别用时 900 秒和 901 秒，只有前者符合时间条件。
