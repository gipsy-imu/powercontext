# 实验知识库技术说明

浏览器读取 UTF-8 笔记，按字符分段，用文件内容的 SHA-256 和分段序号生成稳定 ID，再批量生成 384 维向量。浏览器向本地应用后端发送向量与原文，后端使用 seekdb-js 按库名写入，提交后刷新索引。相同内容在同一个库中只写入一次。用户可切换库名，搜索结果显示文件名与原文片段。

浏览器用 Transformers.js 运行固定版本的 MiniLM ONNX。默认优先 WebGPU FP16，WebGPU 不可用或运行失败时使用 WASM INT8。界面显示推理后端和精度。FP32 对照使用独立集合。seekdb 对同一集合构建 BENG 全文索引和 HNSW 余弦向量索引，通过原生 `DBMS_HYBRID_SEARCH` 执行混合查询及 RRF 融合。 [模型与版本](https://huggingface.co/Xenova/all-MiniLM-L6-v2/tree/751bff37182d3f1213fa05d7196b954e230abad9)

## 本地测量

在 Apple Silicon macOS、Chromium 156 和嵌入式 seekdb 上，用 12 篇自编英文实验笔记与 8 条有标注的查询进行测量。每种配置的单条与批量推理交替运行三次，下表报告中位数。模型初始化从本地 HTTP 模型文件开始。混合查询耗时包含 8 次查询各自生成向量、访问本地 API 和读取结果的开销。

| 指标 | WebGPU FP16 | WebGPU FP32 | WASM INT8 | WASM FP32 |
| --- | ---: | ---: | ---: | ---: |
| 模型与分词文件（字节） | 46,010,502 | 91,100,283 | 23,685,047 | 91,100,283 |
| 模型初始化（ms） | 279.2 | 280.0 | 317.5 | 271.9 |
| 12 条单条推理（ms） | 87.3 | 95.1 | 323.2 | 297.7 |
| 12 条批量推理，批上限 8（ms） | 35.2 | 50.7 | 343.8 | 326.8 |
| 写入与索引刷新（ms） | 40.09 / 422.51 | 34.46 / 414.12 | 51.38 / 318.30 | 48.49 / 209.24 |
| 混合查询向量 / seekdb / 端到端（ms） | 5.80 / 1.64 / 12.10 | 6.05 / 1.66 / 12.10 | 7.95 / 1.83 / 15.25 | 6.15 / 1.60 / 11.65 |
| 纯向量 Recall@3 / MRR@3 | 1 / 1 | 1 / 1 | 1 / 1 | 1 / 1 |
| 混合 Recall@3 / MRR@3 | 1 / 0.9375 | 1 / 0.9375 | 1 / 0.9375 | 1 / 0.9375 |

同机用 `curl` 分别下载三个权重各一次，FP32、FP16 和 INT8 分别耗时 9.60、6.01 和 3.14 秒。这个网络样本与上表的浏览器模型初始化分别计时。FP16 模型文件约为 FP32 的一半，WebGPU 上批量推理比逐条快约 60%。WASM INT8 文件约为 FP32 的四分之一，此次测量中推理较慢。8 条查询的标注原文均进入前三，结果仅覆盖此样例。

从界面的「复现模型与检索对比实验」可重新运行并下载报告。原始样本见 [WebGPU 报告](benchmarks/webgpu.json) 和 [WASM 报告](benchmarks/wasm.json)。启动与操作见 [README](README.md)。
